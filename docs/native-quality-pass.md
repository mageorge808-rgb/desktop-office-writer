# Native Android quality pass

This pass adds Ctrl+O/Ctrl+N while editing, a guarded Ctrl+Alt+T shortcut to the native Table Properties dialog, and preservation of WriterEditorActivity when the upstream document-switching path reopens its base class. Launcher buttons also use the dark palette.

The workflow uses an Android 15 Google APIs x86_64 emulator on a standard free Ubuntu runner. ABI support is recorded and the real ARM64 APK must install and run through its ARM translation bridge; unsupported translation fails rather than passing a substitute. The smoke test uses a separately signed, test-only provider/instrumentation APK. Tests use a disposable DOCX and never user files. They open the engine, insert text and a table, save through a content URI, verify saved DOCX XML, then force-stop/reopen and check read-only mode. A keyboard phase injects native Android key events for typing, Ctrl+B, Ctrl+S and Ctrl+Alt+T, checks persisted bold text, and waits for the real Table Properties dialog. Emulator viewport bounds are 1280 × 854 density 160, approximately the Pad 7's aspect ratio. Actual Pad 7 resolution, input hardware and HyperOS behavior are not simulated fully.

The initial Android 11 run caught a redundant upstream WRITE_EXTERNAL_STORAGE gate: the manifest deliberately omits that permission, so the editor finished instead of using the existing scoped URI grant. The subclass now resumes the pinned private document loader after confirming the content URI remains readable. Real write grants still determine editability; no broad permission is claimed or granted. The packaging step checks that the pinned loader method exists. The old emulator's WebView 83 also requires a newer test image for modern editor JavaScript. Android 13's x86 image could not install the ARM64 APK; Android 15 reports x86_64,arm64-v8a and passed the open/edit/table/save/reopen/read-only checks in run 38130370287, with WebView 124. Initial load measured 15.6 seconds and subsequent loads 10.7–13 seconds on that cloud runner, not on the Pad 7.

Native diagnostics record ABI support, measured load time, instrumentation output, screenshots and logcat. A failure prevents publication of the new installable artifact. The last successful APK remains available until its normal retention expires. This does not certify all Word features or matching Word layout. The native edit screenshot reproduces poor contrast of black DOCX table borders on a dark page. The matched engine's SwTabFramePainter preserves document border colours outside high-contrast mode. Recolouring saved borders or forcing global monochrome rendering would change document behaviour, so this rendering issue remains open. Dark table-picker contrast is tested separately and is improved.
